### GAP-01: Copula `是` — Phân loại đầy đủ

v14 đề cập `是...的` cleft nhưng thiếu các dùng pháp khác của `是`.

#### 1.1 Nhận diện/định nghĩa (predicative)

```
他是林动         → hắn là Lâm Động
这里是危险地带   → đây là vùng nguy hiểm
```

Rule: `S 是 N` → `S là N`

#### 1.2 Xác nhận/nhấn mạnh

```
就是他           → chính là hắn
正是如此         → chính là như vậy
还真是           → thật sự là
确实是           → quả thật là
```

Rule: adv + `是` → adv_vi + `là`

Mapping:

```
就是   → chính là / đúng là
正是   → chính là
确实是 → quả thật là
还真是 → thật sự là
的确是 → đúng là
竟然是 → hóa ra là / lại chính là
```

#### 1.3 Adversative `是...但/却` (acknowledge-concede)

```
这是真的，但我不接受   → đây là thật, nhưng ta không chấp nhận
他是强了，但还不够     → hắn đúng là mạnh hơn, nhưng vẫn chưa đủ
```

Rule: `S 是 ADJ/真的, 但` → `S đúng là/thật sự ADJ, nhưng`

#### 1.4 `是否` yes/no interrogative

```
是否可以进入？   → liệu có thể vào không?
他是否知道       → liệu hắn có biết không
```

Rule: `是否 + V/ADJ` → `liệu có + V/ADJ + không` hoặc `có + V/ADJ + hay không`

#### 1.5 Copula trong extended predicate

```
他是一名修炼者   → hắn là một tu luyện giả
这是我见过的最强战士 → đây là chiến sĩ mạnh nhất ta từng gặp
```

Rule: `S 是 NUM + CLS + N` → `S là một + CLS_vi + N_vi`

### GAP-02: `有` — Ba dùng pháp phân biệt rõ

v14 đề cập existential sentence một phần (mục H trong v7). Cần bổ sung đầy đủ.

#### 2.1 Existential (tồn tại)

```
山顶有人         → trên đỉnh núi có người
林中有灵气        → trong rừng có linh khí
```

Rule: `LOC + 有 + NP` → `ở/trong LOC + có + NP`

#### 2.2 Possessive (sở hữu)

```
他有一件法宝     → hắn có một pháp bảo
我有一个问题     → tôi có một câu hỏi
```

Rule: `S + 有 + NP` → `S + có + NP`

#### 2.3 Approximation `有 + NUM` (estimation)

```
有三百人         → có đến khoảng ba trăm người
有五六米高       → cao chừng năm sáu mét
有十年了         → đã được khoảng mười năm rồi
```

Rule: `有 + NUM/approx` → `có đến/chừng + NUM`

#### 2.4 `没有/没` — negation of 有

```
没有人知道       → không có ai biết
他没有法宝       → hắn không có pháp bảo
从未有过         → chưa từng có
```

Rule: `没有 + NP` → `không có + NP`  
Rule: `从未有过` → `chưa từng có`

#### 2.5 Negative existential `没有 + N + V + 过` (experience)

```
没有人见过如此              → chưa ai từng thấy như vậy
没有任何修炼者能做到这件事  → chưa có tu luyện giả nào có thể làm được điều này
```

### GAP-04: Pivot Sentence (兼语句)

Đây là cấu trúc HOÀN TOÀN bị bỏ qua trong v14.

**Định nghĩa:** Câu mà O của V1 đồng thời là S của V2.

```
他叫我离开
S   V1  O=S'  V2
→ Hắn bảo tôi rời đi
   S   V1  O'  V2
```

**Các V1 pivot thường gặp:**

```
叫/让/使/令/命令 → bảo/khiến/ra lệnh
请               → mời/nhờ
劝               → khuyên
帮/帮助          → giúp
派               → phái/cử
允许/许可        → cho phép
禁止/阻止        → cấm/ngăn
教               → dạy
派遣             → phái đi
```

**Examples:**

```
老师叫我回答问题    → thầy gọi tôi trả lời câu hỏi
他请我喝茶          → hắn mời tôi uống trà
他们派人追来        → họ phái người đến truy đuổi
她劝他不要去        → nàng khuyên hắn đừng đi
他帮我解决了问题    → hắn giúp tôi giải quyết vấn đề
他命令士兵前进      → hắn ra lệnh cho binh lính tiến lên
```

**Rule:**

```
S + V1_pivot + O + V2 [+ O2?]
→ S + V1_vi + O + V2_vi [+ O2?]
```

Phân biệt với causative `让/叫` trong passive context (v14 PART A3).

**Pivot verb → VI mapping:**

```python
PIVOT_VERB_MAP = {
    "叫": "gọi/bảo",      # causative=bảo, literal=gọi
    "让": "để/bảo",
    "使": "khiến",
    "令": "khiến/ra lệnh cho",
    "命令": "ra lệnh cho",
    "请": "mời/nhờ",
    "劝": "khuyên",
    "帮": "giúp",
    "帮助": "giúp",
    "派": "cử/phái",
    "派遣": "phái đi",
    "允许": "cho phép",
    "禁止": "cấm",
    "阻止": "ngăn",
    "教": "dạy",
    "逼": "ép/bắt buộc",
    "逼迫": "ép buộc",
    "劝说": "thuyết phục",
```

### GAP-05: `而` conjunction — 4 loại chưa được phân biệt

`而` trong v14 gần như không được đề cập nhưng rất phổ biến trong văn xuôi.

#### 5.1 Sequential `而` (then/and then)

```
他转身而去       → hắn quay người rời đi
登高而望         → leo cao rồi nhìn xuống
```

Rule: `V1 + 而 + V2` → `V1 + rồi + V2` hoặc merged `V1 V2`

#### 5.2 Adversative `而` (but/yet)

```
他强而无用       → hắn mạnh nhưng vô dụng
大而无当         → to lớn nhưng vô dụng
```

Rule: `ADJ1 + 而 + ADJ2_negative` → `ADJ1 nhưng ADJ2`

#### 5.3 Manner `而` (by way of)

```
挺身而出         → đứng ra phía trước
挥手而去         → vẫy tay rồi rời đi
一笑而过         → cười một cái rồi bỏ qua
```

Rule: Thường là thành ngữ/idiom → guard bằng Trie trước

#### 5.4 Progressive/additive `而` (furthermore)

```
弱小而又渺小     → nhỏ bé lại còn yếu ớt
聪明而有力量     → thông minh lại có sức mạnh
```

Rule: `ADJ1 + 而 + (又) + ADJ2` → `ADJ1_vi mà lại ADJ2_vi`

**Data file cần tạo:** `conjunction_er_map.json`

### GAP-07: Negation Scope — Phức tạp hơn v14

v14 có `没有任何`, `全都不`, nhưng chưa cover:

#### 7.1 Double negation → affirmation

```
没有什么不可能   → không có gì là không thể / tất cả đều có thể
无不 + V        → đều + V (không ai không V)
莫不 + V        → không ai mà không V
```

Rule:

```
没有 + N + 不 + V → tất cả N đều V
无不 + V → đều + V
```

#### 7.2 Negative extent `一点也不 / 一丝也不`

```
一点也不强      → không hề mạnh chút nào
丝毫不差        → không sai một chút nào
```

Rule: `一点/丝毫 + 也/都 + 不 + V/ADJ` → `không hề + V/ADJ + chút nào`

#### 7.3 Negative rhetorical `哪里 + V (negative)`

```
哪里知道他会来  → nào ngờ hắn lại đến
哪能这么简单    → sao có thể đơn giản thế được
```

Rule: `哪里/哪能 + V` → `nào ngờ/sao có thể + V`

#### 7.4 `并不 / 并非` — emphatic negation

```
并不是那么简单  → không hề đơn giản như vậy
并非如此        → không phải như vậy / chẳng phải như vậy
```

Rule: `并不/并非 + P` → `không hề + P` (stronger than plain 不)

### GAP-08: Quantifier Float (数量词游移)

```
他们三个都来了   → cả ba người họ đều đến
这些书我买了五本 → trong số những cuốn sách này tôi đã mua năm cuốn
那些人死了一大半 → trong số những người đó đã chết đi quá nửa
```

**Vấn đề:** Quantifier có thể xuất hiện ở vị trí khác với danh từ nó bổ nghĩa.

**Rule:**

```
NP + V + NUM + CLS → V + NUM + CLS + NP_vi
hoặc: giữ nguyên thứ tự khi tự nhiên
```

**Phổ biến trong xianxia:**

```
强者死了无数     → vô số kẻ mạnh đã chết
弟子倒下了一批   → một đợt đệ tử ngã xuống
```

### GAP-09: Coverb/Serial Prep Chain

```
他从北方向南走来    → hắn từ phương Bắc đi về phía Nam đến
她在月光下向他微笑  → nàng dưới ánh trăng mỉm cười với hắn
```

**Vấn đề:** Nhiều giới từ chồng nhau trước V → thứ tự trong VI khác ZH.

**ZH order:** [FROM] [TO/AT] [DIRECTION] V  
**VI order:** V [từ FROM] [về phía/đến TO]

**Coverb map:**

```python
COVERB_MAP = {
    "从": "từ",
    "向": "về phía/đến",
    "朝": "về phía",
    "往": "đến/về phía",
    "对": "với/đối với",
    "给": "cho",
    "在": "ở/tại",
    "到": "đến",
    "经过": "qua",
    "沿着": "dọc theo",
    "围绕": "xung quanh",
}
```

**Algorithm:**

```
1. Detect coverb chain trước V
2. Nếu có FROM (从) + TO (向/往) → "từ FROM đến TO + V"
3. Nếu chỉ có AT (在) → giữ AT sau hoặc trước tùy V
```

### GAP-11: Ellipsis và Pro-drop

Tiếng Trung thường bỏ chủ ngữ/tân ngữ trong chain:

```
他进来了，看了看，走了出去
→ hắn tiến vào, nhìn một cái, rồi bước ra đi
(shared subject: 他)
```

**Vấn đề:** Khi clause segmenter tách, subject bị mất.

**Rule:** Với chain clauses phân tách bởi `，` không có connector logic, nếu không có explicit subject → inherit subject từ clause trước.

**Không apply khi:**

- Câu có explicit subject mới
- Câu có discourse marker mới (虽然/但是)
- Câu là quoted speech

### GAP-12: Abstract/Philosophy Nominalization

Xianxia và Hồng Hoang lịch có nhiều:

```
圣位之下皆蝼蚁         → dưới Thánh Vị đều là sâu kiến
天道即为规则            → Thiên Đạo chính là quy tắc
大道三千，各有归处       → ba nghìn đại đạo, mỗi thứ đều có chỗ về
```

**Vấn đề:** Những câu này có cấu trúc danh ngữ phức tạp, không phải SVO đơn giản.

**Pattern: `N/NP 即为/乃是 N/NP`**

```
X 即为 Y    → X chính là Y
X 乃是 Y    → X chính là Y (cổ)
X 即 Y      → X tức là Y / X chính là Y
```

**Pattern: `N 之/的 N，各/皆/都 VP`**

```
大道三千，各有归处
→ ba nghìn đại đạo, mỗi thứ đều có chỗ về
```

Rule: `NUM + N, 各/皆/都 + VP` → `NUM + N, mỗi/đều + VP`

### GAP-14: Degree Adverb Interaction với Comparison

v14 có comparison `比/更/最` và degree complement `得`. Chưa có interaction:

```
他比我更快得多    → hắn nhanh hơn tôi nhiều
他比我强很多      → hắn mạnh hơn tôi rất nhiều
他比谁都强        → hắn mạnh hơn tất cả mọi người
这比任何时候都危险 → điều này nguy hiểm hơn bất cứ lúc nào
```

**Rule bổ sung cho comparison:**

```
A + 比 + B + ADJ + 得多 → A ADJ_vi hơn B nhiều
A + 比 + B + 更 + ADJ + 得多 → A càng ADJ_vi hơn B
A + 比 + 谁/任何人 + 都 + ADJ → A ADJ_vi hơn tất cả
A + 比 + 任何时候 + 都 + ADJ → A ADJ_vi hơn bất cứ lúc nào
```

### GAP-15: Multi-subject / Double Subject

```
这件事，他心里清楚    → chuyện này, hắn hiểu rõ trong lòng
那个地方，我去过      → nơi đó, tôi từng đến
林动，他的修为很高    → Lâm Động, tu vi của hắn rất cao
```

**Vấn đề:** Câu double subject (TOPIC + SUBJECT) khác topic-comment thông thường ở chỗ SUBJECT trong comment có pronoun reference trở lại TOPIC.

**Rule:**

```
TOPIC + ，+ [pronoun/N ref to TOPIC] + VP
→ TOPIC + ，+ VP (với pronoun/N được resolve về TOPIC)
```

**Phân biệt:**

```
那本书，我看了           → topic-comment (TOPIC = object of 看)
那本书，他很喜欢         → topic-comment (TOPIC = object of 喜欢)
林动，他的修为很高       → double subject (林动 = antecedent của 他)
```

### GAP-16: Embedded Conditional

```
如果你能突破的话，到时候我们就可以离开了
→ nếu ngươi có thể đột phá, thì lúc đó chúng ta có thể rời đi rồi
```

**Vấn đề:** `到时候` (at that time) refers back to conditional → cần xử lý temporal reference.

**Pattern:**

```
如果 + C1 + 的话，+ 到时候/那时候 + C2 + 了
→ nếu + C1, thì lúc đó + C2 + rồi
```

**Embedded concession:**

```
哪怕他明知道会失败，也要去试试，因为不试怎么知道？
→ dù hắn biết rõ sẽ thất bại, hắn vẫn phải thử, vì không thử sao biết được?
```

### GAP-22: Reduplication đầy đủ (AABB / ABB / AAB / A里AB)

v14 đề cập VV/V一V. Chưa cover:

#### 22.1 AABB (adjective reduplication)

```
干干净净   → sạch sẽ tinh tươm
高高兴兴   → vui vẻ hớn hở
清清楚楚   → rõ ràng rành mạch
结结实实   → chắc chắn vững chắc
```

Rule: AABB adjective → tìm trong Trie; nếu không có → adjective + adjective (reduplicate meaning)

#### 22.2 ABB (verb/adjective + reduplication suffix)

```
红彤彤   → đỏ rực / đỏ ối
白茫茫   → trắng xóa / trắng mênh mông
黑漆漆   → tối đen / đen kịt
亮晶晶   → sáng lấp lánh
软绵绵   → mềm mại
```

Rule: Lookup trong `abb_reduplication_map.json`

#### 22.3 A里AB (pejorative reduplication)

```
糊里糊涂   → lơ mơ / không rõ ràng
迷里迷糊   → mơ màng
马里马虎   → cẩu thả / qua loa
```

Rule: Pejorative reduplication → tìm trong Trie / idiom guard

### GAP-23: Classifier + Demonstrative Interaction

```
这三位长老    → ba vị trưởng lão này
那两枚丹药    → hai viên đan dược kia
这样一个人    → một người như vậy
```

**ZH order:** DET + NUM + CLS + N  
**VI order:** NUM + CLS + N + DET

**Rule:**

```
这/那 + NUM + CLS + N → NUM + CLS_vi + N_vi + này/đó/kia
```

```python
    "那些": "những...đó/kia",
    "此": "này (classical)",
    "彼": "kia/đó (classical)",
```

### GAP-24: Time Expression Reorder

ZH đặt time trước VP; VI thường giống nhưng có ngoại lệ:

```
他明天会来        → ngày mai hắn sẽ đến (time giữ đầu OK)
他来了三天了      → hắn đã đến được ba ngày rồi (time CUỐI → đảo)
他等了足足三个小时 → hắn đợi suốt ba tiếng đồng hồ (intensifier + time)
```

**Pattern: V + 了 + DURATION + 了 → đã V + được/suốt + DURATION + rồi**

```
他修炼了百年了    → hắn đã tu luyện được trăm năm rồi
她等了三天了      → nàng đã đợi được ba ngày rồi
```

**Rule:**

```
V + 了 + NUM + TIME_UNIT + 了[final]
→ đã + V + được + NUM + TIME_UNIT + rồi
```

### GAP-25: Entity Possession Chain

```
林家的大长老的弟子    → đệ tử của Đại trưởng lão Lâm gia
道宗的掌门的法宝      → pháp bảo của chưởng môn Đạo Tông
```

**Vấn đề:** Chuỗi sở hữu lồng nhau với entity.

**Rule:**

```
ENTITY1 + 的 + ROLE + 的 + N
→ N của ROLE của ENTITY1
(VI đảo ngược thứ tự)
```

**Example:**

```
道宗的掌门的法宝
→ pháp bảo của chưởng môn Đạo Tông
(không phải "pháp bảo của chưởng môn của Đạo Tông")
```

Khi entity đứng trước role, merge: `ROLE của ENTITY` → `ROLE + ENTITY` (xianxia: chưởng môn Đạo Tông)

## PHẦN 2 — Cấu trúc Số Còn Thiếu

### 2.1 Số âm, số dưới 0

```
零下三十度    → âm 30 độ / -30°C
负数          → số âm
负五楼        → tầng âm 5 / tầng B5
```

**Rule:**

```
零下 + NUM + 度 → âm NUM độ
负 + NUM       → âm NUM
地下 + NUM + 层 → tầng hầm NUM / tầng B-NUM
```

### 2.2 Số có chữ số đơn vị kết hợp

```
三十七万五千八百二十一人
→ 375.821 người
```

**Vietnamese large number:**

```
万 = 10.000 (vạn)
亿 = 100.000.000 (ức)

Policy:
- Số < 100.000: spell hoặc digit tùy context
- Số ≥ 100.000: digit với dấu chấm phân cách
- Số có 万: có thể giữ "vạn" trong xianxia (ba vạn linh thạch)
```

### 2.3 Percent > 100%

```
百分之一百二十    → 120%
超过百分之百      → vượt quá 100%
百分之两百        → 200%
```

**Rule:**

```
百分之 + NUM (where NUM > 100)
→ NUM% (không convert về fraction)
```

### 2.4 Approximate Percent

```
百分之七八十    → khoảng 70–80%
百分之八九十    → khoảng 80–90%
```

**Rule:**

```
百分之 + paired_digits (e.g., 七八, 八九)
→ khoảng paired_percent_range%
```

### 2.5 `成` ratio đầy đủ

```
九成    → 90% / chín phần mười / chín thành
九成以上→ trên 90%
七八成  → khoảng 70–80%
```

**Mapping:**

```python
CHENG_MAP = {
    "一成": "10%",
    "二成": "20%",
    "三成": "30%",
    "四成": "40%",
    "五成": "50%",
    "六成": "60%",
    "七成": "70%",
    "八成": "80%",
    "九成": "90%",
    "十成": "100%",
}
```

**Context policy:**

```
- Confidence/probability: narrative → "chín phần mười" / technical → "90%"
- After 把握/胜算: spell form preferred
```

### 2.6 Floor/Building Number

```
三四栋三四十层楼的大楼    → ba bốn tòa nhà cao ba bốn mươi tầng
第五层                     → tầng năm / tầng thứ năm
负一层                     → tầng hầm một / tầng B1
地下三层                   → ba tầng hầm / tầng B3
```

**Rule:**

```
第 + NUM + 层 → tầng thứ NUM
NUM + 层楼   → NUM tầng (height attribute)
负/地下 + NUM + 层 → tầng hầm NUM / tầng B-NUM
```

### 2.7 Generation/Wave Number

```
第五代主战斗机        → máy bay chiến đấu chủ lực thế hệ thứ năm
第一波               → đợt đầu tiên / làn sóng đầu
第二批               → đợt thứ hai
```

**Rule:**

```
第 + NUM + 代 → thế hệ thứ NUM
第 + NUM + 波 → làn sóng/đợt thứ NUM
第 + NUM + 批 → đợt thứ NUM / lô thứ NUM
```

### 2.8 Ranking Position

```
第九千七百一十一位低等地精族
→ tộc Địa Tinh cấp thấp xếp thứ 9.711
```

**Rule:**

```
第 + NUM + 位 → vị thứ/xếp thứ NUM
```

### 2.9 Score/Stat Numbers

Trong game/system context:

```
防御值：1200          → Phòng thủ: 1.200
攻击力提升了300点      → Sức tấn công tăng thêm 300 điểm
生命值恢复至上限       → Máu hồi phục về mức tối đa
```

**Rule:** System stat numbers → Arabic digits, đơn vị giữ nguyên nghĩa.

## PHẦN 9 — Known Limitations v15

```text
1. Ellipsis/pro-drop (GAP-11): Detect subject sharing qua chain clauses — 
   MVP chỉ handle cùng câu, chưa cross-sentence.

2. Register mixing (GAP-10): Câu có ≥3 classical indicators 
   → xác định tốt; 1-2 indicators → có thể nhầm.

3. Abstract nominalization (GAP-12): Câu triết học dài nhiều tầng 
   → shallow parser thiếu depth → fallback lexical order.

4. VO idiom guard: Chỉ cover 200+ entries phổ biến; 
   các idiom hiếm hơn vẫn có thể bị tách sai.

5. 而 conjunction disambiguation: Manual labeling khó; 
   các trường hợp ambiguous → fallback sequential rule.

6. Quantifier float trong câu dài: Chỉ handle simple patterns; 
   embedded float → fallback.

7. Pivot sentence chains dài (A让B让C做D): 
   Chỉ handle 1 pivot level; deeper chains → fallback.
```
